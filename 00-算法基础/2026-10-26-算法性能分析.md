# 算法性能分析学习笔记（2026-10-26）

## 1. 快速幂：function3 和 function4 的对比
- `function3` 把 `function3(x, n/2)` 调用了**两次**，每往下一层调用次数翻倍，总调用次数约为 2n，所以还是 O(n)。
- `function4` 先用 `t` 把结果存一次，再算 `t*t`（n 为奇数时再乘 x），每层只调用一次，是 O(log n)。
- 一句话总结：**先算一次，结果复用。**
- 坑：如果 function4 不写 `int t`，而是直接写 `if (n%2==1) return function4(x,n/2)*function4(x,n/2)*x;`，就会退化成 function3。

## 2. 空间复杂度
- 空间复杂度说的是程序**运行时占用的内存**，不是可执行文件的大小。
- 有些程序本身很小，但运行时会占用很大的内存。

## 3. C++ 的 `new int[n]`
- `a` 是一个指针，指向一块放 n 个 int 的内存。for 循环从 `i=0` 写到 `i<n`（注意是小于 n，n=10 时最后写的是 a[9]），空间是 O(n)。
- 原文写的 `new int(n)` 应该是 `new int[n]`：用方括号才是真正开 n 个格子，圆括号的意思是只开 1 个 int、值为 n。

## 4. 斐波那契递归（版本一）
- f(n) = f(n-1) + f(n-2)，递归树形状，总调用次数约为 2·fib(n) − 1。
- 时间的紧界是 φⁿ（φ ≈ 1.618），2ⁿ 是上界。
- 把 fib(n-1) 和 fib(n-2) 存进变量不会变快，因为它们是两个不同的值，都得各自算一遍（这一点和快速幂不同）。
- 空间看递归的**深度**，深度是 n，所以空间是 O(n)。时间看节点总数，空间看树的深度。

## 5. 斐波那契版本二：`fibonacci(first, second, n)`
- 把前两个值当参数一路传下去，每次只往前推一格。
- n<=0 返回 0；n<3 返回 1；n==3 返回 first+second；否则返回 `fibonacci(second, first+second, n-1)`。
- 时间 O(n)，空间 O(n)（调用栈深度是 n）。

## 6. 二分查找（预习）
- 在**有序**数组里每次取中间的值来比较：目标比它大就丢掉左半边，比它小就丢掉右半边。
- `mid = L + (R - L) / 2`，这里的 L 和 R 是**下标**，不是数值。
- 普通数组用方括号取值，比如 `arr[mid]`；箭头 `->` 是用指针访问结构体成员时才用的。
- 数组里的数不连续也是一样的写法，`mid-1`、`mid+1` 指的是下标位置。

## 7. 内存：栈和堆
- 栈：函数调用时自动分配、自动回收，速度快，但空间有限。
- 堆：用 `new` 手动申请，要自己 `delete` 释放，否则会内存泄漏。

## 8. sizeof 和内存对齐
| 表达式 | 结果 | 原因 |
|---|---|---|
| sizeof(int) | 4 | |
| sizeof(char) | 1 | |
| sizeof(a) | 400 | 100 个 int |
| sizeof(b) | 100 | 100 个 char |
| sizeof(st) | 8 | int 4 字节 + char 1 字节 + 3 字节对齐填充 |

- 内存对齐：CPU 按固定的宽度读内存，数据的地址最好是这个宽度的倍数。char 跟在 int 后面如果不补齐，读取会变慢，所以编译器会补字节。
- 现在内存虽然便宜，但 CPU 读取速度上的差距还在，所以编译器默认会补齐。真想省空间，可以自己控制对齐方式。

## 9. double
- double 是双精度浮点数，占 8 字节，精度比 float（4 字节）高。
